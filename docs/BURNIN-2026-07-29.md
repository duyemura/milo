**Common failure mode:** The renderer build resolves `GYM_JSON` relative to `apps/renderer/` when invoked directly. Any operator script that shells the renderer with a relative path will fail on `ENOENT: burnin-<slug>/intake/gym.json`. `milo build --gym` already handles this correctly.

**Slowest step:** Intake, specifically the crawl + classification + LLM generation phase. Build and publish are comparatively fast.

---

## Top 3 Recommended Next Fixes

1. **Make `milo build` / renderer invocation resolve `--gym`/`GYM_JSON` to an absolute path.** This removes the CWD footgun entirely. Even though `milo build --gym` works, any runbook or script that bypasses the CLI and calls `pnpm --filter renderer build` directly will hit the same failure.
2. **Validate downloaded asset references after intake.** CFNE published successfully despite a 403 asset, but the missing local file may still be referenced in `gym.json`. Add a post-download pass that either retries transient failures, falls back to the remote URL, or flags broken references before build so the renderer does not fail loudly later.
3. **Improve pricing/program page discovery.** All three gyms needed AI-generated placeholder pages for `programs` and `pricing`. These high-intent pages are often missing from navs or loaded dynamically. Add a dedicated detection pass (sitemap/footer/link text) to reduce reliance on placeholders.
