## Issues surfaced

### 1. Burn-in runner bypassed `milo build` and passed a relative `GYM_JSON`

The first attempt failed because the background runner used `GYM_JSON=burnin-buckhead/intake/gym.json pnpm --filter @milo/renderer build`. The renderer runs from `apps/renderer/`, so the relative path resolved to `apps/renderer/burnin-buckhead/intake/gym.json` which does not exist.

**Fix used in this burn-in:** pass an absolute path (`$PWD/burnin-buckhead/intake/gym.json`) to the renderer.

**Verified:** `milo build --gym burnin-buckhead/intake/gym.json` correctly resolves the path to an absolute path before invoking the renderer. The CLI is not the problem — the operator/script that shells the renderer directly is. Update any runbooks or scripts to use `milo build --gym` rather than setting `GYM_JSON` manually.

### 2. Asset download failures are logged but not acted on

CFNE had a Webflow CDN image that returned HTTP 403. Intake continued and the site still published, but the failed image may be referenced in `gym.json` as a local path that does not exist.

**Recommended follow-up:** after asset download, validate that every image referenced in `gym.json` exists locally; if missing, either retry with a different URL, fall back to the original remote URL, or flag the section for operator review. The renderer currently fails loudly on missing assets, which is correct, but intake should not emit broken local refs.

### 3. Thin-input placeholder pages are predictable

All three gyms needed placeholder pages for `programs` and `pricing`; Buckhead also needed `contact`. This validates the thin-first design, but also shows that pricing and programs pages are often missing from gym navs or are loaded dynamically.

**Recommended follow-up:** improve detection of pricing/program pages from sitemap/footer links, and consider a dedicated LLM pass that asks "where is pricing/program info on this site?" even if no matching page was crawled.

### 4. Log interleaving on concurrent output

CFNE log shows interleaved lines (`[intake] a[intake] asset...`). This is cosmetic but makes log parsing fragile.

**Recommended follow-up:** route intake logs through `console.log`/`console.error` consistently and avoid partial writes; or switch to a structured logger per package.

## Top 3 recommended next fixes

1. **Make `milo build` resolve `--gym` to an absolute path** before invoking the renderer, removing the CWD footgun.
2. **Validate asset references after intake download** so missing local assets either fall back to remote URLs or are flagged before build.
3. **Improve pricing/program page discovery** so fewer gyms need AI-generated placeholder pages for high-intent content.
