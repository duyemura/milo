## THE OPEN DECISION — what is `generate`? (RESOLVED: framing #3)

We picked the **reprojection engine** path: extract the LLM synthesis step out of intake into a reusable `@milo/generate` package, leave `milo intake` untouched as a caller, and add `milo generate --docs <dir>` for on-demand regeneration.

Implementation:
- `packages/llm` now exports `llmJson` and `ChatFn` (shared by intake and generate).
- `packages/schema` now owns the raw crawl artifact schemas (`PageDocument`, `IdentityCrawl`, `BrandCrawl`, `PagesJson`, `LinkMap`) so generate can consume them without depending on intake.
- `packages/generate` exports `generateSite({ chat, model, identity, brand, pages, budgets, context?, business? }) → { gym }`. It deep-validates every section against the `Section` schema inside the LLM retry loop.
- `packages/intake` now produces `context.json`/`business.json` first, then calls `generateSite` for `gym.json`.
- `apps/cli` adds `milo generate --docs <dir> [--out <dir>]`.

This keeps the proven intake path stable while making `gym.json` a true, re-runnable docs projection — the same function future AI editing and reskin will call.
